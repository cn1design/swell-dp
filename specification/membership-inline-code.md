# 【Phase 3 新規要件】会員/非会員のコンテンツ（インラインコード）出し分け実装のキックオフ

スライダーの実装、完璧でした。ありがとうございます！
続いて、本プラグイン（`swell-dp`）のコア価値である「SWELLデザインパターン」の提供において、ユーザーのログイン状態に応じた「コンテンツ（インラインコード）の出し分け機能」を実装します。

■ アーキテクチャの基本方針（セキュリティ担保のため）

1. **ログイン・認証システムについて**
   - ユーザー登録、パスワード暗号化、ログインフォーム生成などの「認証システム自体」は、セキュリティリスクを避けるため自作しません。（これらは Simple Membership などの既存の無料会員プラグインとWP標準のユーザー管理に委ねます）。
   - したがって、DB設計やログインフォームのUI実装は不要です。

2. **本プラグイン（`swell-dp`）が担う役割**
   - あなたには、「現在アクセスしているユーザーがログインしているか（または特定の会員ランクか）」を判定し、デザインパターンのブロック（またはショートコード等）において出力するHTMLを切り替える「レンダリングの条件分岐ロジック」の実装に集中してもらいます。

■ 出し分けの仕様概要

- 対象コンテンツ：SWELLデザインパターンのコピー用コード（インラインコード）
- 【非ログインユーザー（無料/一般）の場合】
  - デザインパターンのプレビュー（見た目）だけを表示。
  - インラインコード（コピーボタン等）は出力せず、「このコードをコピーするには無料会員登録（または有料購入）が必要です」といったCTA（案内メッセージ）を出力する。
- 【ログインユーザー（購入者/会員）の場合】
  - デザインパターンのプレビューと同時に、完全なインラインコード（コピー可能な状態）を出力する。

■ 進行指示
まずはこの設計方針とアーキテクチャに同意し、これを実装するために現在の `swell-dp` のどのファイル（ブロックの `render.php` など）をどのように改修すべきか、技術的なアプローチ（`is_user_logged_in()` や `current_user_can()` の活用など）の提案を返信してください。

#【Phase 3】事前FBへの回答と実装スタート

素晴らしい技術的な指摘とリスク回避の提案、ありがとうございます。SM専用の関数（SwpmMemberUtils）を使用する方針で大正解です。
質問いただいた2点について、以下の通り回答します。

■ 1. 「会員」の定義について
将来的なマネタイズやプラン拡張（無料会員・有料会員の出し分け）を見据え、**【パターンB：特定の会員レベルIDによる許可リスト照合】**で実装してください。

現時点では、無料会員のレベルID（例: 2 など）や有料会員のレベルIDを配列（許可リスト）として設定し、そのリストに含まれるレベルIDを持つユーザーにのみインラインコードを出力する拡張性の高いロジックを組んでください。

■ 2. コードの出力箇所について
対象ファイルの特定はあなたに任せます。swell-dp プラグイン内の inc/ ディレクトリ配下などを検索（grep/read）し、インラインコード（コピーボタン等のHTML）を生成・出力しているPHPファイルを特定してください。

対象ファイルを見つけたら、許可リストに基づく条件分岐を追加してください。

非許可（未ログインまたは権限なし）の場合は、インラインコードのHTML出力を停止し、代わりに「このデザインパターンを利用するには無料会員登録が必要です」という案内（CTA）のHTMLを出力するように改修してください。

■ 進行指示
対象ファイルの特定結果と、実装する条件分岐のコード概要（許可レベルIDの設定方法など）を共有してから、実際のファイル改修（ビルド等が必要な場合はそれも含む）を進めてください。

この指示を出せば、クロードが自動で該当ファイルを見つけ出し、将来のビジネス展開にも耐えうる最強の出し分けシステムを構築してくれます。

# 【Phase 3 再構築】フリーミアムモデルに基づくインラインコード出し分けとUI実装

先ほどの指示は撤回します。本プラグインのビジネスモデルが明確になりました。「基本無料（インラインコード付き）＋ 有料PRO版（クリーンコード＆限定パターン）」のフリーミアムモデルとして、以下の仕様で至急再実装してください。

■ 1. ユーザー状態と出力するコードの定義

- **非会員（未ログイン）**: 「インラインコード（CSS/JS）を含む」HTMLのコピーボタンを出力する。
- **有料会員（レベル2 または 管理者）**: 「インラインコードを含まない（クリーンな）」HTMLのコピーボタンを出力する。
  ※現在 `data-code-clean` などの属性でJS側に制御を渡している場合は、PHP側でログイン判定を行い、出力する属性や変数を切り替えることで対応してください。

■ 2. 「PRO限定パターン」の概念追加とUI制限

- 全パターンのうち一部を「有料PRO版限定」にするための判定フラグ（例: カスタムタクソノミーや、ACF等のカスタムフィールド、あるいは特定のタグ `pro-only` など）を設けてください（実装しやすい方法でOK）。
- **非会員（未ログイン）が「PRO限定パターン」を見た場合**:
  - コピーボタンは出力せず、代わりに「🔒 PRO限定（詳細を見る）」といったCTAボタン（LPへのリンク）を出力する。
  - 視覚的に制限されていることがわかるよう、該当のカード（li要素等）に `is-pro-locked` のようなCSSクラスを付与する。
- **有料会員の場合**: 制限なくクリーンコードのコピーボタンを出力する。

■ 3. フローティングCTAの設置（非会員向け）

- アーカイブ画面（または全画面）において、非会員（未ログイン）にのみ、画面右下などに追従するフローティングボタンを出力してください。
- テキスト例：「インラインコードを消す方法」「PRO版の詳細はこちら」など（設定やフィルターで後から文言・URLを変更できるように）。

■ 進行指示
上記の3つのビジネスロジックを、先ほど作成した `member-access.php` などを活用して実装し、`npm run build` を実行してください。
完了後、非ログイン時に「通常のコピー（インラインあり）」と「PRO限定のCTA」が混在して正しく表示されるか報告してください。

# 【Phase 3.5】マネタイズ動線の完成とPRO特典（UI/権限）の拡張

フリーミアムモデルの土台はできました。ビジネスの動線と有料購入者（Level 2）の利便性を最大化するため、以下の4点を至急実装・改修してください。

■ 1. フローティングCTAのリンク先修正
現在、右下に表示される「インラインコードを消す方法」のボタンのリンク先が意図しないURLになっています。
このボタンのリンク先を、フィルターフック等で簡単に任意のURL（LPや決済ページなど）に設定できるように改修し、デフォルトの飛び先を明確に設定（または変数化）してください。

■ 2. ヘッダーナビゲーションへの「ログイン/ログアウト」動的追加

- 既存の「初回限定の無料相談」の表示は廃止（または削除）してください。
- SWELLのヘッダーメニュー（グローバルナビ）の右端に、ユーザーのログイン状態に応じて動的にメニュー項目を挿入してください（`wp_nav_menu_items` フックなどを使用）。
  - 未ログイン時：「ログイン」（リンク先はSimple Membershipのログインページ等）
  - ログイン時：「ログアウト」（リンク先は `wp_logout_url()`）

■ 3. 有料会員への「インラインON/OFF切り替えボタン」の権限解放

- 現在、画面左下に表示されている「インラインモード ON/OFF」の切り替えフローティングボタンは管理者限定になっていますが、これを「プラグイン購入者（`swell_dp_has_code_access()` が true のユーザー）」にも表示し、機能を利用できるように権限を緩和してください。
- これにより、有料ユーザーは「クリーンコード」と「インライン付き」を自由に切り替えられる最強の特典を得ます。

■ 4. 「PRO限定」の判定UI（チェックボックス）の実装

- デザインパターン（カスタム投稿タイプ）の編集画面（インスペクターのサイドバー）に、「🔒 PRO限定パターンに設定する」というチェックボックスを追加してください。
- この状態を投稿メタデータ（例: `_is_pro_only`）として保存してください。
- フロントエンド出力時、このチェックが入っているパターンかつ、アクセスしたユーザーが「未ログイン（非会員）」の場合：
  - コピーボタンの出力を停止し、代わりに「🔒 PRO限定で解放（LP等へのリンク）」という非会員向けCTAボタンに差し替えてください。

■ 進行指示
上記4点のビジネスロジック・UI改修を行い、`npm run build` を実行してください。
完了後、ヘッダーのメニュー切り替え、PRO限定チェックボックスの挙動、および有料会員でのON/OFFボタンの表示が正しく機能しているか確認して報告をお願いします。
