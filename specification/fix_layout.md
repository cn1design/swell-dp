# 【緊急事態】全デザインパターンのレイアウト大崩壊の即時復旧指示

現在、フロントエンドの全デザインパターンにおいて、FlexboxやGridなどのレイアウトが完全に無効化され、文字が縦に潰れるなどの「壊滅的なレイアウト崩れ」が発生しています。

直近のあなたの作業（不要ファイルの削除、SVG化、UI変更など）のいずれかで、共通CSS（`dp-style.css`）の読み込みが外れたか、SCSSのコンパイルエラーが発生してCSSが空になっている可能性が極めて高いです。勝手な修正は絶対にせず、以下の手順で「原因究明」と「完全復旧」のみを行ってください。

■ Step 1: 原因の特定（Git diff とビルド確認）

1. `git diff` や直近のコミット履歴を確認し、`functions.php`、`enqueue.php`、`swell-dp.php` などで `dp-style.css` のエンキュー（読み込み）を誤って削除・コメントアウトしていないか確認してください。
2. ターミナルで `npm run build` を実行し、SCSSのコンパイルエラー（`_c-media-block.scss` 等での `}` の抜けやパースエラーなど）が発生していないか確認してください。
3. `dp-style.css` の中身を確認し、空っぽになっていないか、最新のスタイルがコンパイルされているか確認してください。

■ Step 2: 即時復旧

- Step 1で特定した原因（エンキューの漏れ、またはSCSSの構文エラー）を直ちに修正してください。
- 修正後、必ず `npm run build` を通してコンパイルが成功することを確認してください。
- 他のUIやロジックには【絶対に一切触れない】こと。復旧作業のみに専念してください。

■ 進行指示
「何が原因で全パターンのCSSが外れていたのか」を具体的に報告し、復旧が完了したことを知らせてください。

# 【Hotfix】SWELL本体のレンダリングバグに対する一時パッチの実装

素晴らしい原因究明です！WordPressコアのレンダリング順序とSWELLの一括置換（`str_replace`）の仕様衝突によるバグであることが完全に理解できました。私たちのコードが原因ではなかったことに安心しました。

SWELL本体（親テーマ）のコードは直接修正できないため、このバグがSWELL公式で修正されるまでの「一時パッチ（Hotfix）」を私たちの子テーマ（またはプラグイン）側に実装します。

■ 実装方針の選択（あなたに最適な方法を選ばせます）
以下のいずれかの方法で、ネストされた標準グループに誤伝播した `is-row` の影響を無効化してください。影響範囲が `dp-wrap` 内（またはデザインパターン内）に限定され、最も安全で堅牢な方法を選択してください。

【案A: PHPでフックして剥がす】
`render_block` などのフックを利用し、ブロックがレンダリングされる最終段階で、DOMツリーやクラス構造を解析し、「親がflexでない本来は標準/縦のグループ」に誤って付与された `is-row` クラスをPHP側で安全に除去する。

【案B: SCSS（CSS）で打ち消す】
`scss/dp-style.scss` 内において、`.dp-wrap` 配下でネストされた `.wp-block-group.is-row .wp-block-group.is-row`（本来 `is-row` ではないはずの内側要素）に対して、強制的に `display: block;` や `flex-direction: column;` などを当ててSWELLの誤爆CSSを上書き・打ち消す。

■ 進行指示

1. 案Aと案B、どちらが今回のケースにおいて「他のレイアウトへの副作用が少なく安全か」を評価し、アプローチを決定してください。
2. 決定したアプローチでパッチコードを実装し、ビルド（必要であれば）を実行してください。
3. 実装完了後、崩れていたレイアウトが元通りに復旧するか確認してください。
