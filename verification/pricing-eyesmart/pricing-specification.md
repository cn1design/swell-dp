# 目的：既存サイトの複雑なHTMLデータからExpanding Gridブロックコードへの正確な変換（テストケース）

現在開発中の「Expanding Grid」ブロックを使用して、既存サイトの料金データを移行します。
以下の「ソースデータ」を解析し、「ベーステンプレート」の構造に完璧に当てはめたGutenバーグブロックコードを生成してください。

## 1. 入力リソース

- **ベーステンプレート (`pricing-eyesmart.html`)**: このブロック構造、HTMLコメント、属性（JSON）をベースにします。メインカラーは `#000000` としてください。
- **ソースデータ (`pricing-fix.html`)**: ここに含まれる「iPhone 16e」の1行分のHTMLデータを解析対象とします。

## 2. データ抽出とテーブル変換の特別ルール

ソースデータには一つのセル内に複数の料金（軽度・重度など）が含まれる場合があります。これらはWordPressのテーブルブロックにおいて、以下のように「1項目1行」に分解して出力してください。

- **例（画面修理の場合）**:
  - 行1: `画面修理 (軽度割れ Aパーツ)` | `¥15,800`
  - 行2: `画面修理 (重度割れ Aパーツ)` | `¥18,800`
- **「要確認」などのテキスト**: そのままテーブルの右側に反映してください。
- **不要なタグの除去**: `<ul>` や `<li>`、`<p>` などの装飾用タグはすべて排除し、純粋な「項目名」と「価格」のテキストのみを `<td>` に入れてください。

## 3. 出力形式（厳守）

以下のネスト構造を維持した1つのHTMLコードブロックとして出力してください。

1.  `expanding-grid-wrapper` (親：mainColor #000000)
2.  `expanding-grid-item` (第1階層：title "iPhone")
3.         `expanding-grid-wrapper` (子)
4.           `expanding-grid-item` (第2階層：title "iPhone 16e")
5.             `wp:table` (解析した料金表)

## 4. 掟の遵守

`WP-BLOCK-DEV-RULES.md` に記録した「掟」を再確認し、特に `save.js` の出力仕様に矛盾しない（InnerBlocksを壊さない）正しいブロックコメント形式で出力してください。

それでは、`pricing-fix.html` のデータを変換してください。

# 目的：複雑なHTMLデータからExpanding Gridブロックコードへの変換テストおよび「移行スキル」の文書化

## 1. 入力リソース（現在のワークスペース内のファイルを参照）

- **ベーステンプレート (`pricing-eyesmart.html`)**: このブロック構造とHTMLコメントをベースにします。メインカラーは `#000000` としてください。
- **ソースデータ (`pricing-fix.html`)**: ここに含まれる「iPhone 16e」のデータを解析対象とします。

## 2. データ抽出とテーブル変換の特別ルール（AIの学習要件）

ソースデータには、一つのセル内に複数の料金（軽度・重度など）が含まれる場合があります（例：`<ul>` や `<li>` で組まれたもの）。

- **例（画面修理の場合）**:
  - 行1: `<td>画面修理 (軽度割れ Aパーツ)</td><td>¥15,800</td>`
  - 行2: `<td>画面修理 (重度割れ Aパーツ)</td><td>¥18,800</td>`

- **不要なタグの除去**: 装飾用タグ（ul, li, p, br, divなど）はすべて排除し、純粋なテキストのみを `<td>` に入れてください。

## 3. 出力形式と保存

1. `expanding-grid-wrapper` -> `expanding-grid-item` (iPhone) -> `expanding-grid-wrapper` -> `expanding-grid-item` (iPhone 16e) -> `wp:table` というネスト構造を厳守したHTMLコメントコードを生成してください。
2. 生成したコードは、現在のワークスペースの直下（ルート）に **`test-iphone16e.html`** として一時保存してください。
